# pyannote Community-1 GPU 部署工作交付报告

更新日期：2026-10-26（含 GitHub 交付范围复核）

## 工作目标

将 pyannote Community-1 说话人分离模型封装为可端到端运行的本机 GPU 系统，支持音频输入、模型推理、说话人时间轴导出和程序接口调用。

## 技术路线与完成内容

采用 PyTorch 原生 CUDA 推理，音频通过 FFmpeg 8.0.1 / TorchCodec 0.9.1 解码，分割与声纹特征提取运行于 GPU，聚类运行于 CPU。

已完成：

1. 运行环境适配：支持从项目目录加载解码运行库、离线模型与自检；GitHub 版本中的 FFmpeg 归档需另行准备。
2. 推理封装：同一次推理导出完整版和官方 exclusive 非冲突版，提供 JSON、TXT、RTTM 格式。
3. 执行入口：单文件、递归批处理和 HTTP 服务；服务复用常驻模型，任务顺序执行。
4. 任务管理：上传、排队、状态查询、结果下载、错误记录与重启后的状态恢复。
5. 验证与文档：输出契约测试、失败隔离测试、真实 GPU 端到端回归及部署说明。

已集成可选 TensorRT FP32 后端：将 WeSpeaker 卷积帧特征部分导出 ONNX 并构建本机引擎，
结合共享帧计算，复用原有分割、fbank、掩码与池化、聚类和官方双输出逻辑。
默认仍为 PyTorch CUDA，通过 `-Backend tensorrt` 显式启用。可选 TensorRT 的五个固定文件
总下载量为 1,539,565,572 字节（约 1.540 GB / 1.434 GiB），安装在项目内，不升级驱动、
不覆盖现有 Conda 包。该数字不包含 Python、PyTorch、pyannote、模型权重和 FFmpeg。
完整方法见 docs/TENSORRT.md。

## 验收结果

环境：Windows、RTX 4060 Laptop 8 GB、Python 3.11.16、torch 2.9.1+cu126、pyannote.audio 4.0.7。

测试音频：huawei_test.wav，181.648254 秒，指定 3 位说话人。

| 验收项 | 实测结果 |
|---|---|
| PyTorch 单文件 GPU 完整运行 | 成功，推理及结果封装约 7.91 秒，不含模型加载 |
| PyTorch HTTP 上传到 GPU 结果返回 | 成功，模型处理及结果封装约 8.16 秒，不含加载、上传与排队 |
| 完整版 | 56 段，重叠 9.500625 秒 |
| 非冲突版 | 60 段，重叠 0 秒 |
| 与既有基线回归 | HTTP 与批处理的全部分段起止时间及说话人标签一致 |
| 异常恢复 | 坏音频处理失败后，后续正常音频仍成功 |
| 单元测试 | 8 项通过 |
| TensorRT GPU HTTP 与批处理 | 通过，坏音频后可恢复，全部分段与既有基线一致 |
| TensorRT 热运行 | 三次平均 1.860 秒；同轮官方 torch 平均 6.538 秒，约提速 3.52 倍 |
| TensorRT 数值检查 | 静音与随机输入、批量 1/7/16 通过；真实样例 embedding 最大差约 2.18e-6 |
| 额外音频回归 | 已有 AMI ES2011c 前 120 秒，三后端的全部分段与标签一致 |

这些结果验证的是工程运行与回归一致性；未据此宣称模型识别准确率提高。

## 演示与复现

在工程根目录的 PowerShell 中，指定接收方实际 Python 路径：

```powershell
.\deploy.ps1 -Mode check -PythonExe python -Backend tensorrt
.\deploy.ps1 -Mode run -PythonExe python -Backend tensorrt -NumSpeakers 3
.\deploy.ps1 -Mode serve -PythonExe python -Backend tensorrt
```

服务默认在 127.0.0.1:8765 监听，详细上传、查询和下载示例见 DEPLOYMENT.md。

本次验收范围为当前 Windows 机器的本地音频说话人分离系统。接收方硬件与环境的迁移验收需在目标机器上执行；ASR 文本、视频座位绑定、跨文件实名身份识别属于后续多模态系统范围。
